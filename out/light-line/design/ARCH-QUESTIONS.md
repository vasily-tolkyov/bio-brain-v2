# light-line-design-p3 — Architecture questions

仅设计，2026-10-22。这里列的是尚未验证的**光接口细节**，不是重新讨论整套架构。推荐默认值已经写入 [WIRING-CHANGES.md](WIRING-CHANGES.md) 和 [PLAN.md](PLAN.md)，但没有把它们当成 Vasily 已批准的新参数，也没有声称实验已通过。

## 已锁定，不再提问

光基座是独立线路；所有层的吸引子都用光基座；上层模块职责与时间展开保持原样。Vasily 原话：「每一层的吸引子基座都用光基座，其它上层建筑和时序展开之类的都不变。」第二层仍然是「把网络按时间展开复制了很多份然后在这些之间建立了 STDP 的连接，最后映射到高层的网络吸引子中」。不保留旧 LIF level2，不用 `BIO_BRAIN_BASE` 开关，也不提出替代 unroll 的方案。

现有代码中的对应位置是：九个时间副本和起始边沿在 `src/unroll.mjs:2-61`；展开后的输入送入 level2 在 `src/learning.mjs:23-31`；higher layer 的创建位置在 `src/action-pipeline.mjs:17-20`。光基座的无方向 rho 更新见 `src/light-base.mjs:127-159`。因此“过去→现在”的方向由副本的时间位置解释，不能偷偷变成光基座的新属性。

## 留给 Vasily 的具体问题

**A. 几路输入同时亮时，怎样保留各自的颜色？** 推荐每个输入口有固定颜色，缺一半提示时仍用原颜色；同时出现的颜色分别求光场，再取每个细胞的最大亮度。学习时，对相同的实际共亮源集合逐个呈现这些颜色；有 K 种颜色就明确记录 K 次原有 rho 更新，不改核心公式。这能避免 wire 的“把所有输入平均成一种颜色”丢失部分提示信息，但多路输入会增加学习次数。依据：`out/light-base/wire/interface-map.md`、Q2；核心一次只接收一个颜色，见 `src/light-base-color-v2.mjs:32-44`、`src/light-base-color.mjs:93-108`。如果你要求“一个观察窗口只能更新一次 rho”，就需要另行冻结颜色呈现安排并重做 L1–L4 的光接口验收；不能悄悄把多次更新叫成一次，也不能用目标标签挑颜色。时间展开和上层控制流不受这个选择影响。

**B. 一直亮着的输入，算几次离线共亮学习？** 推荐按现有100 ms 读出窗口记录实际输入，在窗口结束后离线提交；同一窗口里的相同连续片段不因 `run()` 分块而重复学习。这样教师500 ms 点亮贡献五个训练记录，仍保留原500/300 ms 和12轮上限。依据：`src/readout.mjs:3-4`、`src/learning.mjs:21-32`、`src/io.mjs:9`、`:82-85`；wire 的另一种500 ms/输入变化计数见 `out/light-base/wire/ARCH-QUESTIONS-W0.md` Q4。另一种选择是只在新提示/新 onset 时提交：它减少长时间旧副本造成的单端衰减，但要重新固定教师20次回放的取样安排和学习剂量。两者都只改静态光基座的呈现接口，不改 TimeUnroll；不能按实验结果或种子混用。

**C. 没有人告诉第二层“这是哪一类”，怎样收集 M2 的20次回放？** 推荐先用冻结回放得到的 B>.3 区域做无标签候选聚类，再取每个候选最早20条实际训练记录，按至少10次亮起来确定成员；不足20条只算候选，不能宣布已成形。标签只在读出之后用来解释结果。依据：当前 M2 评估函数有五个固定中心和 `classIndex`，不是可直接拿来运行的无监督分类器（`src/light-base-color-v2.mjs:62-94`）；现有身份聚类结构见 `src/brightness.mjs:138-153`。如果希望由教师分组来规定这20次回放，那么它只能先作为有监督校准/评估，不能据此声称第二层自主形成了时序吸引子；上层无标签映射仍要补验收。固定10/20和B>.3不变。

**D. 意外和目标差额，换成亮度后用什么单位？** 推荐意外量为 `max(0,现实亮度−预测亮度)`，先采用统一.05死区；目标差额为 `max(0,目标亮度−现实亮度)`，通过 `z/(|z|+1)` 接入原动作公式。预测的±500 ms账本、首次命中、逐次落空、目标递归、.3规则门和.75执行门都保留。旧模块自己构造 LIF/抑制网络并数放电，因此仅改导入还不够（`src/novelty.mjs:17-28`、`:46-62`；`src/errors.mjs:23-40`、`:60-81`；原饱和单位见 `src/three-factor.mjs:14-15`）。如果需要不同的亮度灵敏度，建议仅在101/202/303/404/505上标定一个全局死区/增益，并在验收前冻结；不能保留旧 LIF 比较器、伪造放电数，或按动作/场景各设门槛。这是必要的局部信号转换，旧慢抑制响应的数值等价尚无证据。

以上四项是实现前需要明确记录的边界选择。推荐按文档默认值完成调试阶段，再以冻结的光场验收检查它们；设计文件本身不需要等待答复才能交付。核心 N250、m6、eta.2、kappa.2、theta.3、sum/.05、hill 曲线以及独立线路/每层光/原时间展开均不在可选范围。

## 不需要重问，但必须如实报告的限制

**250个细胞的容量。** 原level2按每条逻辑输入配三个E细胞（`src/layer.mjs:15-16`、`:27-30`），新线每个基座固定250个细胞；9×ID输入口的六近邻集合会有重叠。设计保留所有逻辑副本，记录重叠与不可区分情况，用L2–L4的成员分离、目标独占细胞和C′判断是否成功。失败就报告容量/编码失败，不能缩减ID后宣称全架构完成，也不擅自增加N或新层。

**光rho与预测W不是一个东西。** 当前 `learnWindow` 先处理未来账本/三因素，再运行level2（`src/learning.mjs:21-32`）；`readDownward` 说明自己只是测量（`src/downward.mjs:41-43`）。按“其它上层建筑不变”，保留W的创建、命中、落空和未来倒计时，不新增“光吸引子亮了才允许预测”的门，也不从光rho直接生成可执行规则。验收必须同时看高层光区域补全和实际W路径的预测结果，不能只通过其中一项。

**旧验收与新验收的关系。** 已接受的光事实来自 `out/light-base/p4b/REPORT.md`；wire结果是部分接线证据，完整M3–M12有失败/未执行/依赖阻塞（`out/light-base/wire/REPORT.md`、`per-milestone-diagnosis.md`）。本设计给出的.05比较器死区、映射方案和新阶段门槛都是待验证默认值；不会把旧PASS借给新的全光架构，也不会改旧FAIL或封存文件。
