# light-line-design-p3 — Wiring changes

Design only, 2026-10-22. Paths and line numbers refer to the current working tree, including pre-existing uncommitted work. No implementation or new model results are claimed here. Proposed interface choices and acceptance gates below are **design defaults**, not additions to the accepted light-base results.

## Binding direction and evidence boundary

Vasily's locked direction: 「每一层的吸引子基座都用光基座，其它上层建筑和时序展开之类的都不变。」 Level2 remains 「把网络按时间展开复制了很多份然后在这些之间建立了 STDP 的连接，最后映射到高层的网络吸引子中」. Build a separate light line, with light attractors at sensory, motor, body, temporal and any later attractor layers. There is no base-selection switch and no runtime dependency on a legacy spiking/LIF implementation.

The existing conceptual sequence is lower recognition → logarithmic copies → simultaneous upper association → independent downward connections/future slices (`docs/multilayer-architecture-narrative.md:35-71`, `:92-104`; `ARCHITECTURE.md:44-55`). Current code supplies nine copies through `TimeUnroll`, then runs the higher attractor layer on flattened lines (`src/unroll.mjs:51-61`; `src/learning.mjs:21-32`; `src/action-pipeline.mjs:17-20`). Preserve that structure.

The wire adapter is evidence only. Its level1-only dispatch is explicit in `src/layer.mjs:19-20`; its chosen scope and compromises are in `out/light-base/wire/interface-map.md` and `ARCH-QUESTIONS-W0.md`. `out/light-base/wire/REPORT.md`, `per-milestone-diagnosis.md`, `milestone-results.md` and `test-results.md` establish partial integration, not an accepted all-light architecture. In particular, passing the unchanged M0 core checks or isolated spiking novelty checks is not evidence for a light implementation. Missing historical APIs and the `deltas.hit`/`deltas.STDP` mismatch are independently recorded in `out/light-base/wire/historical-api-findings.json`.

## Common boundary: names stay above the light field

Proposed `LightAttractorLayer` owns an optical core, physical B history, a port map, a membership catalogue and an offline presentation queue. Its consumer-facing operations remain construct / run or present / identify / readout / save / restore. `readout` returns the existing `{id,strength}` shape. `freeze` freezes rho, samples and membership learning, while the caller clock, observed B and prediction ledgers continue. There are no `.net.groups`, `.EE.stdp`, `.IE`, `.AFF` or fake `.spikes` aliases. The legacy surfaces being replaced are visible in `src/layer.mjs:34-60`, `:67-113` and `src/core/state.mjs:33-57`.

**Proposed input encoding, shared by all attractor layers:**

1. Keep ordered logical ports. For a level1 group, its six existing afferent positions select subsets of a physical six-nearest cluster, ordered by distance then cell ID. Use a fixed ordinal coordinate `q=(j+.5)/P` for port j among P ports and the frozen `inputSources(q)` geometry. A scalar-sensor input can retain its supplied coordinate directly. No learned class name selects recurrent wiring. Existing six-line grouping already belongs to the IO adapter (`src/io.mjs:6-22`); nearest-six selection belongs to the accepted core (`src/light-base.mjs:112-118`).
2. Keep position coordinate and optical carrier explicit. At level1 use carrier `x=q`; at level2 position belongs to `(A,k)` while carrier `x_A` belongs to the lower port and is retained across its copies. A partial cue retains its port's carrier. Never recompute a weighted-mean color from the surviving cue cells. This is a proposed resolution of wire Q2; its partial/mixed-cue color loss is documented in `out/light-base/wire/interface-map.md`.
3. Query each active carrier independently through the **same** learned core. With port sources Sₚ, amplitude aₚ and carrier xₚ, compute `Bᵖ=aₚ·propagate(Sₚ,xₚ,intensity=1).brightness`; the combined field is `Bᵢ=maxₚ Bᵖᵢ`. Within each query, x stays unchanged on every hop, exactly as in `src/light-base-color.mjs:99-108`. Unequal intensities are handled by separate source solves and max, not by summing or renormalizing light. Keep the per-carrier fields/path witnesses for audit.
4. For a training frame, U is the union of its **externally supplied positive** source sets. Emit one elementary monochromatic presentation `(U,x)` for each distinct active carrier, in sorted numeric order; each invokes the unchanged `learnSources(U,x)` once. This composes accepted operations without changing eta or the color rule. It deliberately means K carriers make K rho updates: an always-co-lit pair becomes `1−(1−rho)·.8^K`, an exactly-one-lit existing pair becomes `rho·.96^K`. Log K and every elementary update. This multiplicity is a new interface assumption and a capacity/learning-dose risk, not a proven equivalence to scalar training. Do not silently call it “one update”.
5. Proposed clock default: record fixed absolute 100 ms learning frames, matching the existing readout/learning boundary (`src/readout.mjs:3-4`; `src/learning.mjs:21-32`). A changing IO vector inside a window produces its maximal positive constant-source segments, deduplicated only within that window; split calls do not create extra records. Hold one immutable optical state while observing a frame; commit its queued elementary presentations at the boundary for the next frame. This is offline co-lighting between observations, including during an online session; no learning runs inside a propagation solve. Empty segments produce no update. Freeze suppresses commits, not clock advancement. Segment identity, commit cursor and partial window are persisted.

That cadence makes a held 500 ms teacher cue five observed training frames, while retaining the existing 500/300 ms outer curriculum. Changes from wire's 500 ms/changed-input heuristic are deliberate (`src/io.mjs:9`, `:82-85`; `out/light-base/wire/ARCH-QUESTIONS-W0.md`, Q4). One fallback for the **encoding/cadence boundary as a whole** is to commit only on a new positive cue/onset, keeping the same TimeUnroll and clocks; that reduces sustained-cue depression/dose but changes exposure counts and requires a separately frozen teacher/M2 replay schedule. Do not mix these defaults between phases or choose by seed. This fallback is not permission to replace unroll.

**M2 catalogue proposal:** replay recorded training inputs with channels frozen; find candidates from the resulting B>.3 sets using the existing complete-link J≥.8 clustering structure (`src/brightness.mjs:138-153`), then use the first 20 chronological records in each candidate cluster to compute the 10/20 physical membership. Fewer than 20 records means provisional, not accepted. Replays do not learn. Generalize the counting loop; do not import the five hard-coded centers or `classIndex` into runtime (`src/light-base-color-v2.mjs:63-72`). Labels may annotate a measured pattern after identification for the IO mapping and evaluator only. Use stable catalogue IDs; freeze an ID-to-row mapping for a pipeline lifetime, and version any explicit catalogue rebuild. This discovery extension is unvalidated and must pass L1/L2 separation and completion checks before it can supply higher-layer IDs.

## Level2 temporal on light — the required design

### 1. Reuse the time copies exactly

`u[A,k]=TimeUnroll.lines(t)[index(A)·9+k]`. The nine columns, ascending ID-row mapping, onsets, retained overlapping events, max collisions, original onset strength, half-open bin boundaries and expiry `12800·sqrt(2)` remain exactly those in `src/unroll.mjs:2-10`, `:32-61`. E.g. an A onset is in column6 at age3000 ms; its column center is3200 ms for future prediction (`verify/unroll.mjs:19-30`; `src/predict.mjs:10`, `:101-105`). Advancing a copy is still a bookkeeping copy, not optical propagation or a new temporal learning system.

There is one higher `LightAttractorLayer`, in the same location now occupied by `layer2` (`experiments/m3-pipeline.mjs:14-20`; `src/action-pipeline.mjs:17-20`). Logical time copies remain the input surface. The physical groups assigned to these ports are where inter-copy associations live **inside that higher base**. Do not add a separate recurrent temporal reservoir, a replacement sequence model or a parallel executable rule engine.

### 2. Map ports and cross-copy STDP into the higher light base

Allocate port `(A,k)` its fixed cluster `S[A,k]=inputSources(q[A,k])`, with `q=(index(A)·9+k+.5)/(9·IDcount)`. All clusters live in the same higher N=250 geometry. Keep `x_A` as the carrier of A across its time copies. Source IDs are physical cell IDs; `(A,k)` is routing metadata outside the optical model. This replaces the old `line→three E cells` afferent map (`src/layer.mjs:15-16`, `:27-49`) without changing the flattened lines.

At each training frame, form U from the positive supplied ports, then use the common-boundary elementary presentations. For the example A@6 + B@0, the union includes the actual sources of both ports. Each elementary update makes their co-lit unordered pairs stronger by `.2(1−rho)`; an existing pair with just one supplied endpoint weakens by `.04rho`; neither-lit pairs stay unchanged. Append the elementary carrier x only to co-lit pairs. This is precisely the frozen rule (`src/light-base.mjs:146-159`; `src/light-base-color-v2.mjs:32-44`), applied to time-copy inputs instead of spike/calcium events (`src/stdp.mjs:37-69`). All intra-port and cross-port co-lit pairs follow it; there is no selective teacher-labeled edge creation.

**Direction is not stored in rho.** When reading a cross-copy relation, orient an observed port relation from larger age-column to smaller age-column. The existing forecast convention reads only A@k → B@0, k=1..8, A≠B (`src/downward.mjs:55-63`). A reverse physical path B@0 → A@k is legitimate retrospective completion of the same pattern; it does not become the future rule B@k → A@0. That rule involves different ports and requires its own observed experience. Equal-column associations are static co-occurrences, not positive-delay forecasts. Preserve exact onset timestamps and the existing same-source guards (`src/source-labels.mjs:15-26`; `src/three-factor.mjs:97-125`).

Port sets can overlap. The core contains at most 250·249/2=31,125 unordered pairs; it does not contain `9·IDcount` independent six-cell assemblies by promise. A physical edge shared by several port pairs must be recorded once, with all applicable port projections; do not duplicate rho or treat an absent edge as learned. A decoded relation with no target-exclusive cells is unidentifiable in that probe and cannot pass direction/completion acceptance. This capacity constraint remains even when the logical port count exceeds250. Reject a failed capacity fixture, not the lawful TimeUnroll dimensions; do not silently change N, add layers or shard the network.

### 3. Actual cross-copy light propagation and cue completion

For an observed cue at port p=(A,k), solve the same higher core with `S[p]`, carrier x_A and intensity1, then scale by u[p]. Every hop uses `qᵢⱼ(x_A)=t(rhoᵢⱼ)·matchᵢⱼ(x_A)`. The field is the maximum over source-to-cell path products; multiple cues combine by max. This is a query of actual rho/color channels, not a membership lookup or a copied target template (`src/light-base-color.mjs:84-118`).
